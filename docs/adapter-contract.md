# Контракт транспортного адаптера

Адаптер создаётся фабрикой для конкретного вида обмена. Фабрика получает нейтральные настройки и возвращает объект
методами `СоздатьКонсьюмер(Настройки)` и `СоздатьПродюсер(Настройки)`. Она сама получает секреты из защищённого
хранилища. Общие модули вызывают следующие методы адаптера.

## Consumer

### `Прочитать(МаксимумСообщений, ТаймаутМс)`

Возвращает массив структур:

```text
Топик, Ключ, Тело, Заголовки, Партиция, Смещение, ВременнаяМетка
```

### `Подтвердить(Сообщения)`

Подтверждает offsets переданного пакета. Метод вызывается только после сохранения всех новых сообщений в inbox.

## Producer

### `Отправить(Топик, Ключ, Тело, Заголовки)`

Возвращает структуру:

```text
Успешно, Подтверждено, Код
```

`Успешно` и `Подтверждено` должны быть истинными только после подтверждения брокера.

## Общие правила

- адаптер не хранит пароль, токен или сертификат в структуре настроек обмена;
- исключения преобразуются в короткий стабильный код;
- тело и заголовки не записываются в технологический журнал;
- consumer не включает автоматический commit;
- повторный вызов producer допустим: прикладной получатель должен поддерживать идемпотентность по message id.

Прикладная фабрика обработчика реализует `Создать(Настройки)`. Возвращённый объект должен иметь метод
`Обработать(Сообщение)`. Исключение метода оставляет сообщение в очереди для контролируемого повтора.
