# Структура метаданных

Имена нейтральные. Типы строк и чисел можно сузить под ограничения проекта.

## Справочник `KafkaВидыОбмена`

| Реквизит | Тип | Назначение |
| --- | --- | --- |
| `Включен` | Булево | Разрешает фоновые задания |
| `ПсевдонимБрокера` | Строка 100 | Безопасное имя подключения |
| `ТопикВходящих` | Строка 249 | Топик consumer |
| `ТопикИсходящих` | Строка 249 | Топик producer |
| `ГруппаКонсьюмера` | Строка 150 | Consumer group |
| `КлиентПродюсера` | Строка 150 | Producer client id |
| `РазмерПакета` | Число 6 | Лимит одного запуска |
| `ТаймаутОпросаМс` | Число 9 | Таймаут poll |
| `МаксимумПопыток` | Число 3 | Предел повторов |

Адрес брокера, учётные данные и сертификаты получает транспортная фабрика из защищённого хранилища.

## Перечисления

`KafkaВидыСообщений`: `Входящее`, `Исходящее`.

`KafkaСтатусыСообщений`: `Создано`, `ВРаботе`, `Обработано`, `Ошибка`, `Отклонено`.

## Регламентные задания

- `KafkaПрочитатьВходящие` — получает Kafka-сообщения и сохраняет inbox.
- `KafkaОтправитьИсходящие` — публикует outbox.
- `KafkaОбработатьВходящие` — вызывает прикладной обработчик inbox.

Задания должны быть разрешены на сервере и запускаться независимо.

## Права

Сервисная роль получает чтение настроек и чтение/изменение регистра сообщений. Пользовательские роли не должны иметь
доступ к реквизитам подключения и телам сообщений без отдельной необходимости.
