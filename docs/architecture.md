# Архитектура

## Входящий поток

1. Consumer получает пакет сообщений.
2. Каждое сообщение сохраняется в inbox с уникальным ключом `topic/partition/offset`.
3. Offset подтверждается только после успешной записи всего пакета.
4. Отдельное задание передаёт inbox-сообщения прикладному обработчику.
5. Успех и ошибка фиксируются в очереди независимо от чтения Kafka.

## Исходящий поток

1. Прикладной код атомарно добавляет событие в outbox вместе с изменением бизнес-данных.
2. Producer захватывает доступный пакет короткими блокировками.
3. Сообщение считается обработанным только после подтверждения Kafka.
4. Ошибка переводит сообщение в повторную попытку или в конечное состояние.

## Границы компонентов

- `KafkaИнтеграцияКонтракты` — структуры данных и проверка входных значений.
- `KafkaИнтеграцияХранилище` — inbox/outbox, блокировки и переходы состояний.
- `KafkaИнтеграцияКонсьюмер` — чтение, идемпотентная запись и commit offset.
- `KafkaИнтеграцияПродюсер` — публикация и обработка подтверждений.
- `KafkaИнтеграцияОбработчикВходящих` — передача прикладному обработчику.
- `KafkaИнтеграцияПовторы` — интервалы повторов.
- `KafkaИнтеграцияРегламентныеЗадания` — три точки запуска.
- `KafkaИнтеграцияБезопасныйЖурнал` — журнал без payload и секретов.

Транспортный адаптер изолирует код 1С от конкретной внешней компоненты или HTTP-шлюза.
